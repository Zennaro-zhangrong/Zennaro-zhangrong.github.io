2. 最短工作流程：先完成内容，再验证显示

  1. 只读必要文件。 阅读本文、待修改文章，以及适用的写作指令。保留原有标题、封面、分类、发布日期等信息，按需更新摘要和修改日期。
  2. 列出学习目标。 交代读者起点、文章解决的问题、读完可以独立完成什么，以及适用条件。
  3. 先定目录。 把基础、原理、计算、实现、验证、误区和练习排成学习路线，为主要章节设置稳定锚点。
  4. 完成正文。 每节围绕一个问题，先给直观解释，再给公式与推导，最后给例子或检查方法。
  5. 复算与配图。 用脚本验证核心数值、单位和边界；从同一份参数生成图和正文数值。
  6. 检查 Markdown。 核对 ID、内部链接、图片路径、代码围栏，以及公式里的 Markdown 歧义。
  7. 临时构建。 使用现有 Hugo 生成到系统临时目录，不把整个 public 目录当作本次文章修改。
  8. 浏览器验收。 确认公式真的渲染、目录真的滚到目标位置、图片表格可读；检查桌面和窄屏布局。
  9. 整理交付。 保留文章及所需图片，清理临时脚本，说明验证结果和未验证项。

技术事实优先依据教材、论文、官方文档或工程证据。不确定、可能变化或用户要求查证的内容，应查阅原始来源，并在相关论述附近放置链接。省掉重复的工程阅读，不意味着省掉技术核验。

5. KaTeX：公式要能解析，也要能解释

5.1 行内与独立公式各司其职

行内公式用于符号、短关系和句子中的数值：

误差定义为 $e=r-y_m$，其中 $r$ 是参考值。

实际效果：误差定义为 $e=r-y_m$，其中 $r$ 是参考值。

独立公式用于核心定义、推导和重要结论，公式块前后留空行：

$$
T(s)=\frac{L(s)}{1+L(s)}.
$$

实际效果：

$$ T(s)=\frac{L(s)}{1+L(s)}. $$

说明文字放在公式之外。不要把整段中文塞进数学环境，也不要把长推导硬挤成行内公式。

5.2 推导采用“条件—方程—变形—代入—解释”

可复算的推导至少包括：

  1. 模型假设，例如线性、稳态、零初始条件或未饱和。
  2. 已知量与单位。
  3. 原始方程及采用它的原因。
  4. 关键变形步骤，而不只给首尾两行。
  5. 数值代入与结果。
  6. 单位、数量级、极限情况或回代检查。
  7. 工程含义和失效条件。

例如先说明负反馈关系，再整理：

$$ \begin{aligned} Y &= PC(R-HY),\\ (1+PCH)Y &= PC\,R,\\ \frac{Y}{R} &= \frac{PC}{1+PCH}. \end{aligned} $$

重要结论可以加方框，不要把所有公式都框起来：

$$ \boxed{L=-\frac{U_c}{U}} $$

符号第一次出现时就解释，特别说明“交流相量还是时域采样值”“Hz 还是 rad/s”等容易混淆的约定。

5.3 统一符号、单位和断行

同一个物理量尽量使用同一个符号。确实要复用符号时，明确说明作用域；能换名字时优先换名字。

推荐写法：

\omega=2\pi f
20\log_{10}|G(j\omega)|
\mathrm{PM}=60^\circ
T_s=100\,\mu\mathrm{s}
f_c=300\,\mathrm{Hz}

单位用正体，数值与单位适当分隔。程序里的三角函数、频率和时间单位必须与公式对应。

长公式优先用 aligned 拆行，不要缩小到难以阅读。KaTeX 支持的是数学命令集合，不是完整 LaTeX 文档；不要放入文档类、宏包导入或未经验证的自定义宏。

5.4 两个必须避开的 Markdown 陷阱

陷阱一：公式中独占一行的等号。

PID 文章曾采用如下结构：

$$
左边公式
=
右边公式
$$

当前构建链会把独立等号误识别为 Setext 标题标记，导致公式被拆断，目录还会多出异常条目。单独交给 KaTeX 能解析，不代表经过 Markdown 转换后仍正确。

推荐改成：

$$
\begin{aligned}
F(j\omega)
&= A(\omega)\\
&\quad +jB(\omega).
\end{aligned}
$$

简单等式也可把等号放在前一行末尾；若必须单独成行，可以使用数学关系命令，但一般不如 aligned 清楚。

陷阱二：表格内的原始竖线。

Markdown 使用竖线分列。表格中的绝对值优先写成数学命令：

| 指标 | 公式 |
| --- | --- |
| 误差幅值 | $\lvert1-T\rvert$ |

实际效果：

指标 公式
误差幅值 $\lvert1-T\rvert$

复杂公式放到表格外，表格只保留名称、简短关系和比较结果。

6. 配图：从数据到文件再到正文

6.1 什么时候值得画图

适合配图的内容包括：参数变化曲线、方案比较、输入输出波形、注入位置、信号流向和操作流程。简单事实或一条短公式通常直接写文字更清楚。

数学曲线、频响和仿真结果优先用 NumPy、SciPy、Matplotlib 从模型或数据生成。流程图可以绘制为 PNG。若要引入 Mermaid 等渲染依赖，先确认现有支持，不假定它与 KaTeX 一样已经启用。

6.2 文件名包含主题、日期、唯一标记、序号和版本 

主题_日期_本次唯一标记_序号_图意_版本.png

已有 PID 配图示例：

pid_tuning_20261020_a7f3_01_bode_v1.png
pid_tuning_20261020_a7f3_02_injection_v1.png

下次不要沿用 a7f3。使用新的短随机标记或时间标记，写入前检查目标是否存在。随机标记降低撞名概率，存在性检查才是最终保障。

一组图采用相同前缀便于查找。不要覆盖其他文章仍在引用的图片；修订时可更新版本后缀并同步正文链接。

6.3 视觉约定

  • 字体、配色统一，用不同线型或标记区分理论曲线、实测点和参考线。
  • 坐标轴写清变量与单位，例如“频率 / Hz”。
  • 标出关键交越点、峰值或阈值；图例不遮挡主要数据。
  • 网格淡化，数据线比装饰更突出。
  • 图片缩放到正文宽度后，标签仍然可读。
  • 画布可从约 10 英寸宽、150～180 dpi 起步，再依据显示调整。
  • 输出前设置合理布局，避免标题、轴标签和标注被裁切。
  • 明确区分仿真、稳态合成数据与真实实测。

from pathlib import Path
import numpy as np
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

plt.rcParams.update({
    "font.sans-serif": ["Microsoft YaHei", "SimHei", "DejaVu Sans"],
    "axes.unicode_minus": False,
    "font.size": 11,
    "grid.alpha": 0.23,
})

# 传入实际 static/picture 路径与本次唯一文件名。
def make_figure(picture_dir, filename):
    destination = Path(picture_dir) / filename
    if destination.exists():
        raise FileExistsError(destination)

    x = np.linspace(0, 5, 500)
    y = 1 - np.exp(-x)

    fig, ax = plt.subplots(figsize=(10, 5), layout="constrained")
    ax.plot(x, y, color="#2563b9", label="一阶模型")
    ax.set(xlabel="归一化时间", ylabel="归一化输出",
           title="一阶模型的阶跃响应")
    ax.grid()
    ax.legend()
    fig.savefig(destination, dpi=170)
    plt.close(fig)

中文字体必须在运行机器上存在，缺字时更换字体并重新生成。脚本返回成功不等于图中文字一定正常。

6.4 图片紧邻解释，并有清楚图注 

![开环与闭环频响，标出交越频率和半功率带宽](/picture/pid_tuning_20261020_a7f3_01_bode_v1.png)

图 1：按指定教学模型计算。上图用于读开环交越频率，下图用于读闭环带宽；两者不是同一个定义。

替代文字描述图片信息，图注说明数据性质、参数与观察重点。不要只写“如图所示”，也不要把解释放到几屏之外。

6.5 临时文件管理

生成脚本、检查脚本和原文备份优先放在本次专用的系统临时子目录，避免被当作文章或公开资源发布。

如果把脚本放入 static/picture，结束时只删除本次创建且不再需要的脚本。不要用宽泛通配符清理 picture，不要删除正文仍在引用的图。

用户要求保留可复现实验代码时，将其作为正式交付明确命名和说明，不要当临时文件删除。

返回目录

7. 文字、表格与代码：靠结构获得舒适感

7.1 一段展开一个主意

每段通常几句话，先说结论或问题，再解释原因。用空行分段，不用连续空格或大量换行模拟布局。

加粗留给定义、关键结论和容易误解的条件。避免整页加粗、连续感叹号、花哨符号和层层提示框。

每节最好能回答一个具体问题：概念解决什么、公式从哪来、怎么计算、代码对应哪个量、怎样验证，以及最容易在哪一步弄错。

7.2 表格用于对照，不承载长篇推导

适合表格的内容：符号与单位、方法比较、实验参数、现象—原因—操作、误区—解释—纠正方法。

一般控制在 2～4 列，每格短句。需要多段解释时拆成正文。宽表在手机上容易难读，交付前应检查窄屏显示。

7.3 代码交代运行边界

代码块注明语言，例如 python、c、powershell 或 text，并说明它是完整程序、伪代码还是工程片段。

交代输入输出、单位、采样率、参数来源、调用方需要提供的变量，以及错误和边界处理。实时控制代码还要说明哪些工作不能放进中断。

公式、代码与图表使用相同符号，或明确映射关系。例如公式中的积分增益与代码中已乘采样周期的系数，不能同名却不解释差别。

7.4 用练习检查理解

长教程末尾放少量练习，覆盖关键概念区分、数量级计算或数据判断，并给出答案或验证步骤。

工程流程的每步应有具体输出。例如“保存复数幅相与限幅标志”比“认真测量”可执行。把学习目标写成能够解释、计算、实现和验证的能力，不承诺一篇文章解决所有工程问题。

返回目录

8. 构建与验收：三层检查缺一不可

8.1 源文件检查

  • 元信息保留正确，日期真实；需要公式时有 math: true，长文有 toc: true。
  • 主要 ID 唯一，目录链接和返回链接有对应目标。
  • 图片真实存在，正文采用 /picture/ 路径，新文件未撞名。
  • 代码围栏正确闭合，公式没有独立等号或表格竖线歧义。
  • 没有未替换的占位图、数值、模板文字或未说明变量。
  • 核心计算已复算，图和文使用相同参数。

检查时排除代码示例。 本文展示的模板锚点、图片路径和数学式只是示例，不能将它们全部当作本文的真实链接或待渲染公式。

8.2 使用 Hugo 构建到临时目录

下面命令假设当前 PowerShell 目录是 博客根目录/content/post：

$blogRoot = (Resolve-Path '..\..').Path
$previewRoot = Join-Path $env:TEMP (
    'article_preview_' + [guid]::NewGuid().ToString('N').Substring(0, 8)
)
New-Item -ItemType Directory -Path $previewRoot | Out-Null

$oldResourceDir = $env:HUGO_RESOURCEDIR
try {
    $env:HUGO_RESOURCEDIR = Join-Path $previewRoot 'resources'
    $hugoArgs = @(
        '--source', $blogRoot,
        '--destination', (Join-Path $previewRoot 'site'),
        '--cacheDir', (Join-Path $previewRoot 'cache'),
        '--noBuildLock'
    )
    & (Join-Path $blogRoot 'hugo.exe') @hugoArgs
    if ($LASTEXITCODE -ne 0) {
        throw 'Hugo 构建失败，请先处理相关错误。'
    }
}
finally {
    $env:HUGO_RESOURCEDIR = $oldResourceDir
}

命令将网页和本次资源缓存放到临时目录。不要添加清理整个目标目录的参数，也不要把预览构建当作正式发布。

检查草稿或未来日期文章时，可按需增加 --buildDrafts 或 --buildFuture。普通构建中找不到文章，先查发布日期和 draft 状态。

当前工程已有一些主题或配置弃用提示。警告与失败要区分：无关的历史提示通常不需要扩大范围修改；影响页面功能的问题则需要定位。

8.3 KaTeX 语法检查只是第一关

可用现有本地 KaTeX 模块检查提取出的实际数学式：

// katexModulePath 指向现有的 katex.min.js。
// formulas 是剔除代码示例后提取出的实际数学式列表。
const katex = require(katexModulePath);

for (const formula of formulas) {
    katex.renderToString(formula.tex, {
        displayMode: formula.display,
        throwOnError: true,
        strict: "error",
    });
}

只数双美元符号是否成对是不够的；简单正则也可能误处理代码、嵌套围栏和行内内容。以 Markdown 解析结果和最终页面为准。

PID 文章的实际教训：409 处公式通过语法检查，但最初网页只渲染了 408 处。 浏览器检查发现独立等号被当成标题；修正后才达到 409 处渲染、零错误、没有残留公式源码。

8.4 检查生成 HTML

至少核对主要标题 ID 唯一、内部链接有目标、配图对应真实输出文件、KaTeX 与自动渲染脚本已加载，以及模板代码没有被误解析成真实标题或目录。

不要只靠猜测文件名定位生成页面。可以从输出目录、已知 URL 或文章固定锚点找到目标 HTML。

8.5 浏览器检查实际显示

可在临时 site 目录启动仅监听本机的服务：

$siteDir = Join-Path $previewRoot 'site'
python -m http.server 8765 --bind 127.0.0.1 --directory $siteDir

端口被占用时换空闲端口，不要关闭其他服务。检查结束后停止本次服务。

验收内容：

  1. 目录定位： 实际点击开头导航、侧栏和返回目录，查看是否落到正确标题。
  2. 公式显示： 无红色错误、残留源码、异常标题或被截断的长公式。
  3. 图片显示： 滚到每张配图，确认加载、中文、标注和图例正常。
  4. 表格与代码： 列未被误拆，代码可读，横向滚动局限在必要的内容块。
  5. 窄屏布局： 正文不会撑宽整个页面，导航可用，表格和公式不遮挡内容。

DOM 中的公式和错误元素数量可辅助检查，不能替代视觉检查。代码框里展示语法的美元符号是正常内容，不应误判为公式渲染失败。

图片可能懒加载，必须到相应位置核对；重新构建后刷新页面，避免检查旧版本。

9. 出问题时定点排查，不重新扫描工程

现象 按顺序检查 必要时才读的文件
预览里没有文章 日期、draft、构建输出和实际 URL 目标文章元信息
所有公式显示源码 math: true、脚本加载、浏览器报错 config/_default/params.yml；layouts/partials/afterFooter.html
只有一条公式异常 独立等号、围栏、分隔符、表格竖线 目标文章附近几行
公式能解析但网页不完整 生成 HTML 是否拆断数学块 hugo.toml 中的 passthrough 配置
没有侧栏目录 toc: true、是否使用 Markdown 标题 目录相关局部模板
目录跳错或出现空条目 ID 重复、链接拼写、意外 Setext 标题 目标文章与 HTML
图片 404 网页路径、大小写、实际文件和构建输出 对应图片
图片中文变方框 本机字体、绘图警告 本次绘图脚本
表格被拆成多列 单元格里的原始竖线 该表格源码
正文留有路径或占位符 是否误贴输出、模板是否替换完 目标文章
修改后页面不变 是否构建、刷新，是否打开正确预览 本次构建日志
文件写入失败 实际路径与工具授权范围 当前工作区信息

需要搜索时，从目标文件或相关小目录开始，限制类型、行数和匹配数量。避免输出压缩 JS 全文，也避免在错误工作目录执行全盘搜索。

读取 Git 状态前，先确认仓库根目录确实是目标工程，再只看本次文章和配图。不要把用户主目录中其他项目的状态全部列出来。

10. 下次直接使用的写作指令

复制下面的指令，再补充主题和目标文章：

请先阅读 content/post/文章排版方法.md，再阅读本次目标文章。
按手册整理或撰写教程，不必重新浏览整个工程。

保留目标文章原有元信息，按需启用 math: true 和 toc: true。
使用清晰学习路线、稳定章节锚点、可点击目录和返回导航。
数学推导说明假设、符号、单位、变形步骤和适用边界。

需要配图时，从可复算的数据生成到 static/picture，
采用新的唯一文件名，并在正文使用 /picture/ 路径引用。

完成后检查计算、目录与图片链接，进行 Hugo 临时构建，
并在条件允许时检查浏览器实际公式显示、定位及窄屏排版。
只在遇到明确问题时定点读取相关配置或模板。
清理本次不需要的临时脚本，交付文章路径和验证结果。

这份文件不会仅因为存在于文章目录中就自动被所有助手读取。 下次请求中明确提到它，或者直接附上文件，是最可靠的使用方式。

交付说明应简洁，列出实际修改的文章、主要内容、图片数量、验证结果，以及尚未验证的事项。使用当前真实文件路径，不沿用旧用户名。

以后如果换主题、调整数学分隔符、改变图片目录或构建流程，应先验证新流程，再更新本文对应小节。这样，下次写作仍然可以从这一份手册开始。
